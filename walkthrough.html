1.0 System Overview & End-to-End Architecture
Full-Stack Design

The application is a full-stack real-time voice system. The browser captures microphone audio. The browser streams raw audio over a WebSocket to an Express Node.js server. The Express server proxies the audio stream directly to Google Gemini Multimodal Live API on Vertex AI. Gemini processes the audio and returns synthesized voice audio and structured tool calls.

REAL-TIME BIDIRECTIONAL STREAMING PIPELINE
1
Audio Capture in Browser (Client-Side)

An AudioContext worklet records user speech at 16,000 Hz single-channel PCM format. Base64 chunks stream across the WebSocket every 200 milliseconds.

2
WebSocket Proxy (server.js)

The Node.js server receives the client stream at /ws/live. It signs Google Cloud credentials with GoogleAuth and proxies data to Gemini Live on Vertex AI.

3
Gemini Live Model & Sub-Agent Tool Execution

Gemini executes registered tool calls (such as flight rebooking, hotel layover booking, and dining vouchers). It returns 24,000 Hz PCM audio to the browser for instant playback.

⚡ Latency Target

Glass-to-glass audio latency stays under 400 milliseconds. Audio playback starts immediately when the model generates sound chunks.

🛑 Voice Interruption

The system supports instant voice interruption. When the user speaks, the client stops audio playback and flushes the queue immediately.

🛡️ Fallback Resilience

If the Vertex AI connection fails or an API times out, local sub-agent simulators execute tools with pre-loaded configuration data.

3.0 Sub-Agent Tools & Function Calling Engine
API & Tool Schema

The Gemini Live agent coordinates multiple sub-agents through structured tool declarations. The model inspects member state and automatically triggers appropriate sub-agent tools during the voice call.

Core Registered Tool Declarations

  • get_guest_profile: Reads card member tier, upcoming trip details, and active travel disruption alerts.
  • rebook_flight_itinerary: Holds and issues priority alternate flights with waived airline change fees.
  • book_chicago_layover_hotel: Reserves immediate airport accommodations during severe weather delays.
  • issue_disruption_dining_voucher: Creates and issues a $100 American Express dining credit voucher.
  • adjust_hotel_reservation: Adjusts check-in dates at destination hotels and waives modification fees.
  • update_transfer_schedule: Reschedules private chauffeur airport pickups to match new arrival times.
  • book_dining_reservation: Reserves tables through Global Dining Access by Resy.
  • end_conversation: Concludes the voice call session cleanly and confirms all bookings.

5.0 Backend Data Architecture, Determinism & Database Layer
Data & Persistence

This section explains how data storage, data determinism, and backend persistence operate across the system.

📁 Is a Database Used?

No external database engine (such as PostgreSQL, MySQL, MongoDB, or Firestore) runs in this demo application.

The backend stores application state in local JSON files and in-memory browser memory. Node.js file system methods (fs.readFileSync, fs.writeFileSync) manage session persistence on the local disk.

🎯 Deterministic vs. Dynamic Elements

Deterministic Data: Member profiles, disruption records, flight hold inventories, hotel options, and policy rules reside in static JSON files in public/data/configuration/.

Dynamic AI: Gemini Live dynamically understands speech, decides tool calls, and generates audio responses in real time over the WebSocket connection.

In this architecture, Gemini Live generates conversational voice fluidly, but all transactional actions execute through rigid, deterministic tool schemas.
